# 管理者建置教學（從申請 LINE 官方帳號開始）

> 這份是給「系統擁有者」的，只需要做一次。完成後，出題的人只需要看 [02-出題者操作手冊](02-出題者操作手冊.md)。
>
> 預估時間：第一次做約 60～90 分鐘。全程免費。

## 系統怎麼分工（先看懂這張表，後面比較不會迷路）

| 東西 | 放哪裡 | 公開嗎 |
|---|---|---|
| 網頁程式（玩家答題頁、管理後台） | GitHub Pages | 公開（只是程式，沒有題目） |
| **題目、正解、題庫、作答紀錄** | **Cloudflare D1 資料庫** | **不公開**，只有你的後端讀得到 |
| LINE 憑證（Channel access token）、管理密碼 | Cloudflare Worker 的「機密」設定 | 不公開 |

玩家掃碼後，網頁會拿他的 LINE 身分去向後端要題目；後端確認身分才把題目（**不含正解**）傳給他。玩家按送出後，也是由後端比對正解、算分。所以就算有人打開瀏覽器開發者工具，也看不到正解。

> 為什麼用 Cloudflare 而不是 Google Apps Script？實測 Cloudflare 一次呼叫約 0.15～0.35 秒，而且很穩定；Apps Script 一次約 1～3 秒，偶爾會卡到 10～20 秒。專案裡的 `gas/Code.gs` 是舊版後端，留作備份，新系統不需要它。

## 你需要先有

| 帳號 | 用途 | 沒有的話 |
|---|---|---|
| 個人 LINE 帳號（手機） | 申請官方帳號、之後用來測試 | 手機裝 LINE 註冊 |
| Cloudflare 帳號 | 後端與資料庫（免費方案） | https://dash.cloudflare.com/sign-up |
| GitHub 帳號 | 放網頁程式 | https://github.com/signup |

出題者**不需要**任何帳號，只要後台網址和管理密碼。

## 整體流程與「記事表」

整個流程會拿到 5 個值，請邊做邊填進下面這張表（**帶 🔒 的是機密，不能貼給別人、也不能寫進 GitHub**）：

| # | 名稱 | 在哪一步取得 | 你的值 |
|---|---|---|---|
| A | 官方帳號 Basic ID（含 @） | 步驟 2 | `@` |
| B | 🔒 Channel access token | 步驟 3 | |
| C | LIFF ID | 步驟 4 | |
| D | 🔒 管理密碼 ADMIN_KEY（自己想一個） | 步驟 6 | |
| E | 後端 Worker 網址（`https://…workers.dev`） | 步驟 6 | |
| F | 🔒 Channel secret（建議設定） | 步驟 3 | |

```
步驟1 申請官方帳號 → 2 官方帳號設定 → 3 啟用 Messaging API → 4 建 LINE Login channel + LIFF
      → 5 GitHub 放網頁 → 6 Cloudflare 後端 + 資料庫 → 7 填 config.js → 8 設定 Webhook
      → 9 登入後台、看示範測驗 → 10 手機實測 → 11 上線前檢查 → 12 交接給出題者
```

## 步驟 1｜申請 LINE 官方帳號

1. 用電腦開 https://account.line.biz/signup ，選「以 LINE 帳號登入」，手機上確認登入。
2. 依畫面填寫：
   - **帳號名稱**：玩家會在聊天室看到，請取正式一點的名字（例如「○○考場互動測驗」）。事後可以在 Official Account Manager 修改。
   - **電子郵件**：填你自己的。
   - **業種**：選最接近的（例如「學校」）。
3. 送出後完成。**帳號類型維持「未認證帳號」即可，不需要申請認證。**
   - 未認證帳號不會出現在 LINE 名稱搜尋結果，只有知道基本 ID 或加好友連結的人才找得到，這正好符合我們的用途。
4. 方案：預設就是**免費的「輕用量」方案**，維持不動。
   - 本系統回覆成績用的是 Reply API（玩家傳訊息後，我們「回覆」），**回覆訊息不計入每月則數、沒有上限**。
   - LINE 的方案價格偶爾會調整，實際以 [LINE 官方說明](https://tw.linebiz.com/) 為準。

✅ 完成標誌：你進得去 https://manager.line.biz/ 並看到剛建立的官方帳號。

## 步驟 2｜官方帳號基本設定

1. 進入 https://manager.line.biz/ → 點你的官方帳號。
2. **記下 Basic ID**：畫面左上角帳號名稱旁，格式像 `@123abcde`。填入記事表 **A**。
3. 右上角「⚙ 設定」→「**回應設定**」，調成：
   - **自動回應訊息：關閉**（不關的話，玩家傳訊息時會被 LINE 預設的自動回覆搶先回應）
   - **Webhook：先不動**（它是灰的，要等步驟 8 填了網址才能開）
   - 加入好友的歡迎訊息：隨你，可留著或改成活動說明
   - 聊天：開或關都可以

## 步驟 3｜啟用 Messaging API，拿 Channel access token

1. 在 manager.line.biz →「設定 → **Messaging API**」→ 按「**啟用 Messaging API**」。
2. 會要你選「Provider（服務提供者）」：選「建立服務提供者」，取個名字（例如「現場測驗」）。隱私權政策、服務條款網址都是選填，留空按「確定」。
   - ⚠️ **記住這個 Provider 名稱**，步驟 4 的 LINE Login channel 一定要建在**同一個 Provider** 底下，否則無法連結。
3. 開 https://developers.line.biz/console/ （同一個 LINE 帳號登入，第一次會要你登錄開發者姓名與 email，填你自己的）→ 點你的 Provider → 會看到一個 **Messaging API** 類型的 channel。
4. 進入該 channel →「**Messaging API**」分頁 → 拉到最下面「**Channel access token (long-lived)**」→ 按 **Issue** → 複製那一長串。填入記事表 **B** 🔒。
5. 同一個 channel 的「**Basic settings**」分頁有 **Channel secret**，複製起來填入記事表 **F** 🔒。它用來讓後端確認 webhook 訊息真的是 LINE 送來的（建議設定，不設也能用）。

## 步驟 4｜建立 LINE Login channel 與 LIFF App

> LIFF 不能建在 Messaging API channel 底下，必須建在 **LINE Login channel**。所以這裡要另外建一個。

1. 在 LINE Developers Console，進入**同一個 Provider** → 「**Create a new channel**」→ 選 **LINE Login**。
2. 填寫：
   - Company or owner's country or region：**Taiwan**（只是登記地區，海外玩家一樣能用）
   - Channel name：例如「Exam LIFF」（玩家授權登入時會看到）
   - Channel description：隨便寫一句
   - **App types：勾選「Web app」**
   - Require two-factor authentication：建議**關閉**
   - Privacy policy / Terms of use URL：選填，留空
   - 勾同意 LINE Developers Agreement → Create
3. **連結官方帳號**（才能偵測玩家有沒有加好友）：該 channel →「**Basic settings**」→「**Linked LINE Official Account**」→ Edit → 選你的官方帳號 → Update。
4. 進入「**LIFF**」分頁 → **Add**，填寫：

   | 欄位 | 填什麼 |
   |---|---|
   | LIFF app name | 現場測驗 |
   | Size | Full |
   | **Endpoint URL** | `https://<你的GitHub帳號>.github.io/<repo名稱>/play/` ← **結尾的 `/` 不能省**，帳號名稱**要小寫**。帳號與 repo 名稱先照步驟 5 打算取的填，之後可以改 |
   | Scopes | 勾 **profile**（也可勾 openid） |
   | Add friend option | **On (Aggressive)** |
   | 其他 | 維持預設（Scan QR、Module mode 都不用開） |

5. 按 Add，畫面會出現 **LIFF ID**（格式 `2001234567-AbCdEfGh`）。填入記事表 **C**。

> 此時 LINE Login channel 狀態是「**Developing**」，只有你（channel 管理員）和被加為 Tester 的人能開啟。**正式活動前要切成 Published**，見步驟 11。

## 步驟 5｜GitHub：放網頁程式

repo 裡**只有網頁程式，沒有任何題目或正解**，所以設成 Public 是安全的（GitHub Pages 免費版也需要 Public）。

1. 登入 GitHub → 右上角 **＋ → New repository**：
   - Repository name：例如 `quiz-repo`（英文小寫、數字、`-`）
   - **Public**
   - **不要**勾「Add a README file」，其他也都不用選 → Create repository
2. 把這個專案資料夾的內容上傳（二選一）：

   **方法 A：用 git（推薦）** ── 在專案資料夾開終端機：
   ```bash
   git init -b main
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/<你的帳號>/<repo名稱>.git
   git push -u origin main
   ```
   第一次 push 會跳出瀏覽器要你登入 GitHub。

   **方法 B：網頁上傳** ── 在 repo 頁面按「uploading an existing file」，把資料夾內**所有檔案與資料夾**（含 `.nojekyll`）拖進去 → Commit changes。

3. 開啟 GitHub Pages：repo →「**Settings → Pages**」→ Build and deployment：
   - Source：**Deploy from a branch**
   - Branch：**main**，資料夾 **/ (root)** → Save
4. 等 1～2 分鐘，Pages 頁面上方會出現網址：`https://<帳號>.github.io/<repo>/`。
5. **驗收**：打開 `https://<帳號>.github.io/<repo>/play/?quizId=demo&mock=1`，應該看到「示範測驗」10 題（頁面上方有黃色「測試模式」提示）。這一步還沒接後端，用的是網頁內建的示範題目。
6. 如果你的帳號或 repo 名稱和步驟 4 填的 Endpoint URL 不同，回 LINE Developers → LIFF → 編輯 Endpoint URL 改正。

## 步驟 6｜Cloudflare：後端與資料庫

> 畫面文字可能和下面略有出入，找意思相近的選項即可。資料表**不需要**手動建立，後端第一次被呼叫時會自動建好，並放入一場示範測驗。

**6-1 註冊**：到 https://dash.cloudflare.com/sign-up 用 email 註冊免費帳號，驗證 email。

**6-2 建資料庫**
1. 左邊選單「**Storage & databases**」→「**D1 SQLite Database**」→「**Create Database**」。
2. 名稱填 `quiz-db`，Data location 維持預設「Location」→ **Create**。

**6-3 建後端 Worker**
1. 左邊選單「**Compute**」→「**Workers & Pages**」→「**Create**」→「**Start with Hello World!**」。
2. 名稱填 `quiz-api`（網址會是 `https://quiz-api.<你的帳號>.workers.dev`）。
3. **「Protect with Cloudflare Access」保持關閉**，按 **Deploy**。

**6-4 綁定資料庫**
1. 進入這個 Worker →「**Bindings**」分頁 →「**Add binding**」→ 選「**D1 database**」。
2. Variable name 填 `DB`（**全大寫**），D1 database 選 `quiz-db` → 儲存。

**6-5 貼上後端程式**
1. 回到 Worker 頁面，按右上角「**Edit code**」。
2. 如果編輯器是**唯讀**、上面寫「Only the latest version of your Worker can be edited」：點版本下拉選單，選標示 **Latest** 的那個版本 → **Apply**。
3. 打開專案的 [`worker/index.js`](../worker/index.js)，**整份複製**，在編輯器裡 **Ctrl+A** 全選後貼上（原本的 Hello World 會被取代）。
4. 按右上角「**Deploy**」。

**6-6 設定機密**
1. Worker →「**Settings**」→「**Variables and Secrets**」→「**Add**」。
2. **Type 選 Secret**（不是 Text），加三筆，每加一筆按 Deploy 或 Save：

   | 名稱 | 值 |
   |---|---|
   | `CHANNEL_ACCESS_TOKEN` | 記事表 **B** |
   | `ADMIN_KEY` | 你自己設定的管理密碼（記事表 **D**）。**12 字以上、英數混合**。出題者登入管理後台就是輸入這個 |
   | `CHANNEL_SECRET` | 記事表 **F**（建議設定） |

**6-7 驗收**：Worker 頁面上有一個網址，長得像 `https://quiz-api.xxx.workers.dev`，填入記事表 **E**。用瀏覽器打開它，看到 `LINE quiz backend is running.` 就成功。

> 之後如果修改了 `worker/index.js`，只要到 Edit code 貼上新版再 Deploy，網址和資料都不會變。只改「機密」（例如換管理密碼）按儲存後立刻生效。

## 步驟 7｜填寫 config.js

打開專案的 `config.js`，把記事表的值填進去：

```js
window.APP_CONFIG = {
  liffId: "2001234567-AbCdEfGh",          // C
  apiUrl: "https://quiz-api.xxx.workers.dev",   // E
  oaId:   "@123abcde"                     // A（要有 @）
};
```

存檔後重新上傳/推送（`git add . && git commit -m "config" && git push`），或直接在 GitHub 網頁上開 `config.js` → 右上角鉛筆 ✏️ 編輯 → Commit。等 1～2 分鐘生效。

> `config.js` 裡都是公開資訊，可以放心存在公開 repo。**Channel access token（B）、Channel secret（F）與管理密碼（D）絕對不要寫進去**。

## 步驟 8｜設定 Webhook

1. LINE Developers Console → 你的 **Messaging API** channel →「**Messaging API**」分頁。
2. **Webhook URL** → Edit → 貼上記事表 **E**（Worker 網址）→ Update。
3. 按「**Verify**」，應該顯示 **Success**。（舊版 Google 後端會顯示 302 錯誤，Cloudflare 不會。）
4. 打開「**Use webhook**」。**「Webhook redelivery」保持關閉。**
5. 回到 Official Account Manager 的「回應設定」，確認 **Webhook 已可開啟並且是開的**、自動回應訊息是關的。

## 步驟 9｜登入管理後台，看示範測驗

1. 開管理後台：`https://<帳號>.github.io/<repo>/admin/`
2. 輸入你的管理密碼（記事表 **D**）→ 登入。（第一次呼叫後端會自動建立資料表，可能多等一兩秒。）
3. 你會看到示範測驗。到「**發布 / QRCode**」→ 選它 → 畫面上會出現 QRCode 與網址。
4. 點「開啟『預覽』」，會用真實題目在電腦上作答一次（不會連 LINE、不會記錄成績）。
5. 想自己出一場的話，看 [02-出題者操作手冊](02-出題者操作手冊.md)。

## 步驟 10｜手機實測（最重要）

用**你自己的手機**做完整一輪。要全部通過才算完成：

1. LINE 掃描剛才的 QRCode（或把網址 `https://liff.line.me/<LIFF ID>?quizId=demo` 傳給自己的 LINE 點開）。
2. 若跳出「加入好友」→ 加入官方帳號，回到測驗。
3. 看到 10 題 → 作答（故意漏 1 題）→ 按「檢視作答總覽」→ 確認漏答那題是紅字「尚未作答」→ 按「修改」能跳回該題。
4. 送出 → 短暫顯示「計算成績中…」後出現分數，且顯示「成績已記錄 ✓」。
5. 按「**點我用 LINE 查詢成績**」→ LINE 聊天室打開，輸入框裡已經有「查詢成績 demo」→ 你按送出。
6. **官方帳號在幾秒內回覆「您已完成作答，成績：X/10」** ✅
7. 回管理後台「作答結果」頁，載入示範測驗，看得到你的紀錄 ✅
8. 用「每人限一次」的測驗再掃一次：應直接顯示「您已完成作答」+ 上次成績，不會出現題目（示範測驗本身允許重複作答，要測這項請在後台新建一場，取消勾選「允許重複作答」）。

**卡關了？** 看文末的「疑難排解」。

## 步驟 11｜上線前檢查

- [ ] **LINE Login channel 改成 Published**：LINE Developers → 你的 LINE Login channel → 頁面上方狀態「Developing」→ 切換為「**Published**」。沒切的話，只有你和 Tester 能開，其他玩家會打不開。
- [ ] 官方帳號「回應設定」：Webhook **開**、自動回應訊息**關**
- [ ] Worker 的三個機密都已設定（CHANNEL_ACCESS_TOKEN、ADMIN_KEY、CHANNEL_SECRET）
- [ ] 正式測驗的「允許重複作答」設定符合預期
- [ ] QRCode 印出來後，**再用另一支手機（非你本人）實際掃一次**
- [ ] 現場網路：確認場地有 4G/5G 或 Wi-Fi 給玩家用

## 步驟 12｜交接給出題者

出題者**不需要任何帳號、也不需要碰任何 LINE 或 Cloudflare 設定**，你只要給他：

1. 管理後台網址：`https://<帳號>.github.io/<repo>/admin/`
2. 管理密碼（`ADMIN_KEY`）── **用私訊給他，不要貼在群組或寫在文件裡**
3. [02-出題者操作手冊](02-出題者操作手冊.md)（可以整份轉成 PDF 或直接貼給他）

**不要給他**：Channel access token、LINE Developers / Official Account Manager 權限、Cloudflare 帳號。他不需要這些。

收回權限：到 Cloudflare → Worker → Settings → Variables and Secrets，把 `ADMIN_KEY` 改成新的值，**立即生效**，舊密碼與所有已登入的憑證馬上失效（對方要用新密碼重新登入）。

## 怎麼看作答紀錄

- **後台「作答結果」頁**：選測驗按「載入」，可看統計、每題答對率，並可「下載 CSV」用 Excel 開啟。
- **直接查資料庫**：Cloudflare → Storage & databases → D1 → `quiz-db` → **Console**，輸入例如
  `SELECT ts, quiz_id, display_name, score, total FROM results ORDER BY id DESC LIMIT 50`
- **清除紀錄**：後台「作答結果」頁最下方有「**已刪除測驗的作答紀錄**」區塊，可以清除**測驗已被刪除**的紀錄（還存在的測驗，紀錄不能在後台清除，要先刪除該測驗）。清除前先切到「全部測驗」下載 CSV 備份。
  也可以直接在 D1 Console 執行 `DELETE FROM results WHERE quiz_id = '某場的代碼'`（這樣連還存在的測驗也刪得掉，請小心）。

## 疑難排解

| 症狀 | 常見原因與解法 |
|---|---|
| 掃 QRCode 打不開 / 顯示錯誤頁 | ① LINE Login channel 還是 **Developing**，且掃的人不是管理員/Tester → 改 Published 或把他加為 Tester。② LIFF 的 **Endpoint URL** 打錯（要 https、結尾有 `/`、指到 `/play/`、帳號小寫）。 |
| 「系統尚未設定完成（config.js 缺少…）」 | `config.js` 沒填完，或填完後還沒推上 GitHub / 還沒生效（等 1～2 分鐘，並強制重新整理）。 |
| 「找不到這場測驗」 | 測驗代碼（quizId）與 QRCode 不一致，或測驗已在後台被刪除。 |
| 一直停在「加入好友」畫面 | 玩家實際上還沒加好友；或加完要按「我已加入，繼續」。 |
| 加好友的偵測完全沒作用 | LINE Login channel 沒有連結官方帳號（步驟 4-3），或 LIFF scope 沒勾 profile。系統會略過偵測，不會擋住玩家。 |
| 「連線不穩定」/「送出失敗」 | ① `apiUrl` 貼錯：瀏覽器直接開那個網址應該看到 `LINE quiz backend is running.`。② Worker 的 D1 綁定（`DB`）沒設。③ 玩家登入過期（重新掃 QRCode）。可到 Cloudflare → Worker → **Observability / Logs** 看錯誤。玩家頁上有「重新送出」按鈕，重按不會重複記錄。 |
| 回傳 `server_error` | 通常是 D1 沒綁定成 `DB`，或 Worker 程式貼得不完整。到 Worker 的 Logs 看詳細錯誤。 |
| 按了查詢，聊天室有預填字，但**沒有回覆** | ① 玩家沒按「送出」。② Webhook 沒開，或網址貼錯（Verify 應為 Success）。③ 官方帳號的「自動回應訊息」沒關（LINE 會回預設訊息）。④ `CHANNEL_ACCESS_TOKEN` 貼錯 → 看 Worker Logs 有沒有 `Reply API failed`。⑤ 有設 `CHANNEL_SECRET` 但貼錯 → Verify 會失敗（401）。 |
| 後台登入說密碼不正確 | 要和 Worker 機密 `ADMIN_KEY` 完全一致（注意大小寫、前後空白）。 |
| 後台登入說「嘗試次數過多，暫時鎖定」 | 同一個網路連續輸錯 5 次會鎖 5 分鐘（之後每次鎖期結束只能再試 1 次，第 8 次起鎖 30 分鐘、第 12 次起鎖 24 小時）。等時間過就好；急著解除可到 D1 Console 執行 `DELETE FROM login_guard`。 |
| 後台儲存時說「儲存衝突」 | 有另一個人或另一個視窗同時改了這場測驗。重新整理後再編輯。 |
| 剛改完題目，玩家還看到舊的 | 後端為了加速會把題目在記憶體裡快取，最多約 **10 秒**就會更新。 |
| 編輯 Worker 程式時是唯讀 | 你開的是舊版本：版本下拉選單選標示 Latest 的那個 → Apply。 |

## 進階：後台登入防護

系統已內建，不用設定就有效：

- **失敗次數鎖定**：同一個來源（IPv6 以整段 /64 計）連續輸錯 5 次鎖 5 分鐘，之後越錯鎖越久（30 分鐘、24 小時）。鎖定期間連正確密碼都不受理；同時送出上百次猜測，也只有前 5 次會被檢查。
- **管理密碼不存在瀏覽器裡**：登入成功後，後端發一張 7 天有效、有簽章的「登入憑證」，瀏覽器只保存憑證。憑證的簽章金鑰包含 `ADMIN_KEY`，所以**換掉 `ADMIN_KEY` 就能讓所有人登出**。
- **管理後台網頁的內容安全政策（CSP）**：只允許執行本站的程式，資料只能送往 `*.workers.dev`，也不允許被嵌進別人的網頁。
- 最有效的防護還是**管理密碼夠長夠亂**：建議 16 字以上、英數混合（例如用密碼管理器產生）。

### （選用）再加一層：機器人驗證（Cloudflare Turnstile，免費）

啟用後，登入頁會多出「我不是機器人」的驗證，機器人即使不斷試密碼也過不了這關。

1. Cloudflare 左側選單 → **Turnstile** → **Add widget**（新增小工具）。
2. Widget name 隨意（例如 `quiz-admin`）；**Hostname** 填你的網頁網域（例如 `<帳號小寫>.github.io`，不含 https 與路徑）；Widget Mode 選 **Managed**。建立後會拿到兩個值：**Site Key**（公開）與 **Secret Key**（機密）。
3. Worker `quiz-api` → Settings → Variables and Secrets → 新增一筆 **Secret**：名稱 `TURNSTILE_SECRET`，值貼 Secret Key → Deploy。
4. 把 Site Key 填進 `config.js` 的 `turnstileSiteKey`，推上 GitHub（1～2 分鐘後生效）。
5. 開後台登入頁，應該會看到驗證方塊；驗證通過才能登入。

想關掉：把 `TURNSTILE_SECRET` 刪除即可（登入頁自動不再要求）。**兩邊要一起設**：只設了 `TURNSTILE_SECRET` 卻沒填 `turnstileSiteKey`，登入頁會顯示錯誤、登不進去。

## 已知限制（先知道比較好）

- **題目與正解不在公開的地方**，玩家只有在掃碼、通過 LINE 身分驗證後才會拿到題目（不含正解）。但**通過驗證的 LINE 使用者仍然可以看到題目本身**（他本來就要作答），也可能把題目截圖給別人。要防這個，需要限制誰能作答（例如白名單），有需要再跟我說。
- 管理後台只有一組共用密碼，知道密碼的人可以修改所有測驗。登入憑證是「無狀態」的，按「登出」只清掉這台瀏覽器裡的憑證；要讓**所有**已登入的人立刻失效，請換掉 `ADMIN_KEY`。
- GitHub Pages 不能設定 HTTP 安全標頭，所以後台的防護（CSP、防嵌入）是用網頁內的設定做的，對一般情況足夠，但不如自己的伺服器完整。
- **活動開始後不要再改題目**：改了以後，已作答者的紀錄與「每題答對率」統計會對不上。
- 作答紀錄會包含玩家的 LINE 暱稱與 userId，屬於個人資料。活動結束後請視需要匯出並刪除，並在活動說明告知玩家有記錄。
- **免費額度**：Cloudflare Workers 免費方案每天 10 萬次請求；D1 免費方案每天讀取 500 萬列、寫入 10 萬列、儲存 5 GB（[官方說明](https://developers.cloudflare.com/d1/platform/pricing/)）。每位玩家約用 3 次請求、寫 1 列，一場數百人的活動只會用到零頭。額度政策可能調整，以官方為準。
